# 崩溃检测

BepInEx 启动器包含内置崩溃检测功能，帮助你快速诊断和解决问题。

## 工作原理

当游戏崩溃时，启动器会监控意外退出并自动捕获诊断信息。

### 检测过程

1. 游戏以注入 BepInEx 的方式启动
2. 启动器监控游戏进程是否异常终止
3. 如果检测到崩溃，会弹出对话框，提供导出诊断信息的选项
4. 收集诊断日志并打包供分析使用

## 崩溃对话框

检测到崩溃时，你会看到一个对话框，提供以下选项：

- **导出日志**：将诊断信息保存为可分享的文件
- **查看日志**：打开日志查看器检查崩溃输出
- **关闭**：关闭对话框而不采取任何操作

::: tip
报告崩溃时始终导出日志 - 它们包含诊断问题的关键信息。
:::

## 诊断中包含的内容

诊断导出包括：

- **Logcat 输出**：来自 Android 设备的系统级日志
- **BepInEx 日志**：Mod 框架输出和错误消息
- **系统信息**：设备型号、Android 版本和应用版本

## 导出日志

### 自动导出

检测到崩溃时：
1. 在崩溃对话框中点击 **导出日志**
2. 选择保存位置
3. 诊断文件保存为压缩存档

### 手动导出

你也可以手动导出诊断信息：
1. 转到 **设置 → 导出诊断**
2. 选择保存位置
3. 诊断文件已保存

### 共享日志

导出后，你可以共享诊断文件：
- 通过消息应用分享
- 附加到 [GitHub Issue](https://github.com/NextBep/BepInEx.Android.Launcher/issues)
- 发送给 Mod 开发者寻求帮助

## 常见崩溃原因

| 原因 | 解决方案 |
|------|----------|
| 缺少未剥离的 libunity | 在游戏设置中启用 libunity |
| 不兼容的 Mod 版本 | 更新或移除有问题的 Mod |
| BepInEx 解压失败 | 清除 BepInEx 并重新启动 |
| .NET 运行时问题 | 清除 .NET 并重新启动 |
| 未阻止 Unity Kill | 启用阻止 Unity Kill |

## 崩溃故障排除

如果遇到反复崩溃：

1. 查阅[故障排查](./troubleshooting.md)指南
2. 导出并查看诊断日志
3. 在 **设置** 中清除 BepInEx 和 .NET 缓存
4. 尝试不使用 Mod 启动以隔离问题
5. 在 [GitHub](https://github.com/NextBep/BepInEx.Android.Launcher/issues) 上报告问题并附上诊断文件
